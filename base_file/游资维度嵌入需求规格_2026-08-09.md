# 游资大佬追踪维度 · 嵌入现有 A 股决策 Agent 系统 · 需求规格

> 生成：2026-08-09
> 配套源文件：`base_file/游资大佬追踪体系_2026-08-08.md`（方法论全文，本文件是落地规格）
> 目标：把「游资大佬追踪」作为独立分析维度，嵌入「潜力股发掘 → 建仓 → 持仓监控 → 离场」全链路。

---

## 0. 核心设计原则（务必遵守）

1. **职责分离，铁律不变**：代码只负责「抓取原始数据 → 落库 → 注入 LLM 上下文」；
   **所有主观研判（游资是否标向、题材前瞻、跟买/离场判断）全部交给 LLM**。
2. **提示词可调教**：只改 `agent_prompts/` 下的 .py 提示词文本 或 `global_base_prompt.md`，禁止把研判逻辑写死进代码。
3. **统一注入机制**：游资维度规则优先进 `global_base_prompt.md`（全局基线，所有 Agent 每次都加载）；各业务 Agent 专属的游资用法进各自 Prompt。
4. **数据全部进数据库**：新增游资相关表进现有 `data/dev.db`（SQLite），不走内存/JSON 文件。
5. **监管红线保持**：纯研究辅助，LLM 游资研判只是建议，最终交易由人执行；绝不自动下单。

## 2. 代码职责：数据抓取与注入（backend 层）

### 2.1 新增龙虎榜数据源（`backend/app/datasource/`）
- 新建 `dragon_tiger_source.py`：抓取龙虎榜（东财 lhb 接口 / 上交所 / 深交所），解析为 §1.2 结构。
- 兜底/降级：多源 or 失败降级，符合现有 `datasource/base.py + fallback.py` 模式。
- 可被 schedule（APScheduler）定时拉取（T+1 16:30 后），也可手动触发。

### 2.2 游资聚合（`backend/app/services/` 新建 `capital_view.py`）
- 代码把 龙虎榜记录 按「营业部 → capital_actor 映射」聚合为资本操作记录（§1.3）。
- 按营业部归属到已知游资；**未知营业部**可为 LLM 研判预留字段，不强行归类。

### 2.3 统计（§1.4）
- 定时任务统计各游资历史胜率/盈亏比 → 落库。

### 2.4 注入 LLM 上下文
- Discover/Score/Position/Monitor/Sell 各 Agent 调用时，把「相关标的的游资维度数据」（龙虎榜记录、游资名、净买方向、战绩）注入 prompt 的对应数据段。
- 注入点参照 `backend/app/agents/common.py` 的统一拼接机制。

## 3. LLM 职责：游资研判（提示词层）

### 3.1 全局基线 `global_base_prompt.md`（所有 Agent）
- 游资主体定位：K226 9 大主体中的第②主体（标向性最强、可观察）。
- 游资 7 大骗局识别（K189）：对倒/诱多/砸盘/试盘/洗盘/出货/卖点。
- 游资字段误读防御（K227）：累计涨幅≠PE、瞬时≠全口径、净买入≠全部主力意图、单源≠多源。
- K226 主体权重：机构+游资+北向=3减仓→强派发；游资单减→不一定；游资对倒→警惕。

### 3.2 DiscoverAgent（`discover_prompt.py`）
- 新增游资维度：候选标的是否有「一线/多游资最近净买入」→ 作为潜力股发掘的**加分信号**；
- 多游资同买（题材共振）= 强信号；
- 结合现有 K168 三维 + 5 维评分，游资维度不足一票否决，只作为补充维度。

### 3.3 ScoreAgent（`score_prompt.py`）
- 「资金流向」维度纳入游资信号：游资净买方向、游资等级、是否协同（机构/北向同买）。
- 游资对倒/出货识别 → 资金维度显著扣分。

### 3.4 PositionAgent（`position_prompt.py`）
- 建仓时机：游资净买 + 题材清晰 + 评分≥4维 → 可作为「战术级」建仓候选；
- 但严守 C3 止损（成本×0.92）、敬畏 K225 诚实红线（跟买≠必胜）。
- 游资撤离已现 → 不建仓/慎建仓。

### 3.5 MonitorAgent（`monitor_prompt.py`）
- 新增监控信号：**持仓标的被游资关注**（净买≥阈值）→ 拉升机会；**被游资撤离**（净卖≥阈值）→ 短期见顶预警。
- 结合 K189 骗局验证（对倒/出货）。

### 3.6 SellAgent（`sell_prompt.py`）
- 离场决策纳入游资维度：游资大幅净卖出 / 集体撤离 / 触发 K189 出货 → 减仓/清仓建议；
- 游资净买但机构净卖（信号矛盾）→ 高风险提示，倾向谨慎。

## 4. 实现步骤建议（供 claude code 分阶段执行）

- **阶段 0**：先在 `global_base_prompt.md` 注入游资全局规则（纯 Prompt，最小风险）。
- **阶段 1**：加数据库表（models.py）+ repo.py 读写 + 迁移；
- **阶段 2**：龙虎榜数据源 + 定时抓取 + 聚合；
- **阶段 3**：各业务 Agent 提示词注入游资维度 + LLM 研判；
- **阶段 4**：手动验证（用真实龙虎榜跑一次，看上游资维度生效）。

> 每个阶段应独立可验证，避免一次性大改动引入难排查问题。
