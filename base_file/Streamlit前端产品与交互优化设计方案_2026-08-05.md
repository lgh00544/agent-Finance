# A股决策系统 · Streamlit 前端产品与交互优化设计方案

日期：2026-08-05　|　范围：纯前端展示与交互层，不触碰任何 Agent 研判逻辑、选股方法论、输出 Schema、后端 API 与业务数据

---

## 1. 优化目标与问题根因

### 1.1 现状盘点（已核实，非假设）

现有前端已有良好基础，本次优化是在其之上的系统性升级，不推翻重做：

| 已有能力 | 位置 | 评价 |
|---|---|---|
| 顶部常驻状态栏（时间/账户/指数，60s 刷新 + 失败降级缓存） | render.py `top_status_bar` | 完善，保留 |
| 后台任务状态区（5s 轮询 / toast / 失败重试 / 完成自动刷新） | render.py `task_status_area` | 完善，保留 |
| 候选池懒加载（每批 20 条） | 1_每日候选池.py | 仅此一页有，需推广 |
| 时效标注（浅灰 + 紧急琥珀高亮） | render.py `time_text` | 完善，保留 |
| 原始 JSON 深度折叠 | render.py `raw_json_expander` | 完善，保留 |
| 首页聚合 API（一次并行） | backend /api/dashboard | 完善，保留 |
| 局部刷新（fragment 5s/30m/60s） | app.py / render.py | 完善，保留 |

### 1.2 痛点与根因（按严重度排序）

**P1 视觉体系缺失（体验简陋）**
- 全站无全局主题 CSS，仅 `_TOP_BAR_CSS` 一处内联样式；页面全部是裸 `st.title + st.expander + st.markdown`，无卡片化布局、无统一留白与层级
- 色板散落硬编码：`#F87171 / #4ADE80 / #F59E0B / #60A5FA / #9CA3AF / #FBBF24` 在 6+ 页面重复出现，无统一常量，改一色需动多处
- 无 `.streamlit/config.toml` 主题配置：streamlit 原生控件（dataframe 排序箭头、按钮、selectbox）无深色适配兜底

**P2 列表分页不统一（数据量大时不可用）**
- 硬截断不一致：评分报告 `rows[:10]`、建仓计划 `rows[:10]`、交易复盘 `rows[:10]`、告警日志 `rows[:20]`，截断后无「加载更多」入口 → 历史数据多了之后永远看不到旧记录
- 唯一有懒加载的候选池页，其加载逻辑深埋在页面内（`BATCH/vis_key/session_state`），无法复用

**P3 交互与状态反馈不统一**
- 筛选 `text_input` 无防抖：评分/建仓/复盘页每敲一个字符即全页 rerun + 全量请求，键入中不断闪烁
- 空态文案风格不一（info / caption / warning 混用），失败提示文案格式不一
- 持仓监控页「操作」expander 巨型化：监控按钮 + 卖出决策 + 决策历史 + 人工卖出表单全塞一个 expander，展开后一屏放不下
- 候选池 expander 标题一行塞 5 类信息（rank/代码/名称/评级/类型），可读性差

**P4 数据溯源展示不统一（业务底线）**
- 时间戳标注已有且较好，但「数据源标识 / 置信度 / 前提假设」无统一展示组件：候选池/评分展开里有部分，告警/复盘/对话页格式各写各的
- 强制追溯项必须全站一致呈现，不能依赖各页手写 markdown

**P5 顶部栏可用性小瑕疵**
- 「账户明细 / 指数详情」两个按钮占 `st.columns([1.2, 1.2, 6])` 三列，挤压主内容区首屏宽度；展开详情用普通 markdown 列表，与深色体系不协调

**P6 性能基线（卡顿分类对照）**

| 页面请求类型 | 现状 | 判定 |
|---|---|---|
| 首页聚合 / 候选池 / 持仓列表 / 告警 / 复盘 / 知识库 | 纯 DB 查询，无 LLM | 应秒开；现状除候选池外无分页，长列表滚动卡 |
| 挖掘 / 评分 / 建仓 / 卖出决策 / 监控 | LLM 异步任务 | 已异步 + 任务状态区，达标，保留 |
| 顶部栏 / 任务区轮询 | 60s / 5s fragment | 达标，保留 |

根因归类：**渲染慢**（无分页 + 无卡片化复用）与**交互卡顿**（筛选无防抖）为主，无数据库 N+1 问题（已聚合接口），LLM 链路已异步无需动。

### 1.3 设计因果依据

- 卡片化 + 全局 CSS 变量 → 解决 P1（视觉统一）且纯 CSS 零运行时开销，不牺牲性能底线
- 分页组件抽离复用 → 解决 P2 且同时降渲染压力（P6）
- 统一溯源组件 → 解决 P4，满足「数据可追溯原则」的强制要求，不因美观删减任何字段
- 全部改造在 streamlit 原生组件能力内（CSS 变量 + markdown + expander + dataframe + fragment），不引入任何新依赖、不触碰后端

## 2. 页面结构设计

### 2.1 全局布局（10 页统一，精确数值）

```
┌────────────────────────────────────────────────────────────┐
│ stHeader（原生顶部，2.95rem，z-index 1000）                  │
│ ┌────────────────────────────────────────────────────────┐ │
│ │ 顶部常驻状态栏 top-status-bar（fixed, top 2.95rem,     │ │
│ │   height ~1.35rem 单行, z-index 998）                   │ │
│ └────────────────────────────────────────────────────────┘ │
│ [侧边栏（原生导航，padding-top 4.3rem 避让）] │ 主内容区     │
│  stMain（padding-top 4.3rem 避让状态栏）                    │
│  ┌ 页面标题区：st.title + 页副标题 caption（统一字号）        │
│  ├ 监管红线提示（全站一致，仅首页 + 持仓监控 + 知识库保留）    │
│  ├ 任务状态区（task_status_area，无任务时零渲染）            │
│  ├ 操作区（primary 按钮统一左上，筛选统一右上）              │
│  ├ 内容区（卡片列表 / 表格 / 详情展开）                      │
│  └ 页脚统一 caption（数据口径说明）                          │
└────────────────────────────────────────────────────────────┘
```

- 顶部栏高度与避让：`stMain / stSidebarContent padding-top: 4.3rem`（沿用现有值，全站不变，已验证无遮挡）
- 内容区水平内边距：`padding: 0.4rem 1.2rem 2rem`（统一）
- 卡片间距：垂直 `0.7rem`，页内分区 `st.divider` 全部替换为「分区标题 + 卡片组」

### 2.2 全局组件选型（render.py 新增，全站复用）

| 组件 | 实现 | 用途 |
|---|---|---|
| `apply_global_theme()` | 注入全站 CSS（含 CSS 变量） | 每页标题前调用一次 |
| `card(title, body, meta=None)` | `st.container(border=True)` + 自定义 CSS 类 | 详情卡片化容器 |
| `badge(text, tone)` | markdown `<span class="badge badge-{tone}">` | 评级 A/B/C、状态、标签徽章 |
| `stock_chip(code, name)` | 代码等宽 + 名称，统一标识 | 全站股票标识（沿用 `stock_label` 语义） |
| `trace_line(label, time, source=None, confidence=None)` | 统一溯源行组件 | **强制追溯项统一呈现**（见 §3.3） |
| `record_list(items, render_fn, batch=20, key)` | 懒加载列表（含「加载更多」） | 候选/评分/建仓/复盘/告警全站统一 |
| `empty_state(text)` | 统一空态（icon + 文案 + 操作提示） | 全站空数据提示 |

### 2.3 各页结构（分区变化摘要）

| 页面 | 布局调整 |
|---|---|
| app.py 首页 | 各模块改为卡片组；「手动任务」区置顶为卡片；页脚导航 caption 移除（原生侧边栏已承担） |
| 1_候选池 | 主表保留；expander 改为卡片（标题只放 评级徽章+股票chip+类型，详情内部分段）；懒加载换 `record_list` |
| 2_评分报告 | 筛选区（代码输入 + 确认按钮，防抖见 §4.2）+ 分页列表 + 五维明细卡片 |
| 3_建仓计划 | 同上；批次表保留 dataframe 分页 |
| 4_持仓监控 | 「操作」expander 拆分为两个独立卡片（①信号与决策区 ②人工卖出表单区），每持仓一张卡片而非 expander |
| 5_交易复盘 | 待审核建议卡组 + 复盘分页列表 |
| 6_偏好 | 保留（表单页无需卡片化，仅主题适配） |
| 7_告警日志 | 分页列表 + 详情卡片 |
| 8_知识库 | 新增/批量导入卡片化 + 列表分页 |
| 9_Agent对话 | 保留现有 tab 结构，问答/裁决结果用卡片呈现 |

## 3. 信息字段分层与可追溯规范

### 3.1 分层总则（全站一致）

- **一级信息（列表/卡片默认展示）**：评级徽章 + 代码+名称 + 一句话核心理由 + 生成时间
- **二级信息（展开可见）**：完整结论分段（研判依据/关键价位/风险清单等），模块化小标题
- **三级信息（深度折叠）**：原始 JSON（现有 `raw_json_expander` 机制，全站保留）

### 3.2 一级信息统一规格（列表行/卡片标题）

```
[评级徽章] 600519 贵州茅台　·　吸筹末期　·　2026-08-05 16:12
  一句话核心理由（≤ 1 行，超出省略）
```

- 排序：评级 A→B→C 优先，组内按 rank/时间升序（候选池现状逻辑，推广到评分/复盘列表：日期降序）
- 颜色：评级徽章全站统一 A 深红 / B 橙 / C 蓝（§6.1 色板）

### 3.3 强制追溯项（全站 `trace_line` 统一呈现，禁止删减）

每条业务结论的详情区首行固定展示（缺失则显示「—」，不隐藏）：
1. **生成/检测时间**：YYYY-MM-DD HH:mm（现有 `time_text` 语义并入）
2. **数据源标识**：东财 / 新浪 / 腾讯 / 券商截图 / LLM 生成（候选快照、评分明细等字段级标注）
3. **置信度**：LLM 结构化输出的 confidence / 信心度（无则「—」）
4. **前提假设**：估算值标注「估算」、缓存值标注「上次数据」、过期信号琥珀高亮（沿用现有 highlight 机制）

紧急信号（减仓/清仓建议或 warning/critical 严重度）时间戳琥珀高亮——现有规则，全站统一。

### 3.4 股票标识强制规则

所有股票条目必须同时展示代码+名称，禁止仅显示代码或仅显示名称（沿用 `stock_label` 语义，全站零例外）。

## 4. 性能交互策略

### 4.1 同步/异步边界（固化，不混淆）

| 类型 | 页面 | 交互模式 |
|---|---|---|
| 纯数据查询 | 首页/候选池/评分/建仓/持仓/复盘/告警/知识库/对话历史 | 同步加载，秒开目标 ≤2s（本地 DB） |
| LLM 异步 | 挖掘/打分/建仓方案/卖出决策/监控/对话提问调教学习 | `render.submit_task` 提交即返回 + 任务状态区跟踪，禁止页面内同步阻塞等待 |

### 4.2 加载策略

- **分页统一**：`record_list` 每批 20 条；dataframe 用 Streamlit 原生分页（`height` 限制视口内滚动，避免全量 DOM）
- **筛选防抖**：text_input 筛选区与结果区解耦——输入框外显 + 「查询」按钮确认（或 `st.fragment` 隔离结果区，输入变化仅重跑 fragment），消除键入即全页 rerun
- **折叠按需加载**：详情一律 expander/卡片展开才渲染（现有机制，推广）；原始 JSON 永久默认收起
- **请求层**：api_client 增加统一 `_cached_get`（session_state 短缓存 30s，覆盖顶部栏与首页模块），失败沿用「上次成功缓存 + 标注」（现有 `_bar_stale_fetch` 模式推广）

### 4.3 性能预期指标

- 纯查询页面首屏渲染：≤2s（本地 SQLite/MySQL）
- 列表滚动：分页 20 条/批，滚动不卡（无全量 DOM）
- 任务轮询：任务区 5s（现状，保留）；顶部栏 60s（现状，保留）；热门板块 30m（现状，保留）

### 4.4 前后端分工

- 前端承担：CSS/卡片/分页/防抖/短缓存（本次全部改动）
- 后端承担：无新增要求。现有 `/api/dashboard` 聚合与 `candidates/dates` 轻量日期接口已满足；如需「评分列表分页」，可复用现有 `limit` 参数（已有），不改接口协议

## 5. 交互与状态规范

### 5.1 加载状态

| 场景 | 反馈 |
|---|---|
| 列表/详情加载 | 保留现状（streamlit 原生 spinner 或立即渲染），不做骨架屏（单次本地查询 <1s，骨架屏徒增复杂度；仅 LLM 等待处保留 spinner/任务区） |
| LLM 后台任务 | 顶部任务状态区（运行中琥珀明细 + 完成 toast + 失败一键重试）——现有机制全站统一 |
| 提交重复任务 | 后端 409 → 「XX 正在执行中，请等待其完成后再试」——现有机制保留 |

### 5.2 异常状态（全站统一文案模板）

- 接口失败：`「{模块}加载失败，请确认后端服务正常运行后点击『刷新』重试（{异常类型}）」`——现有 `_fail` 模板推广到全部页面
- 数据为空：`empty_state` 统一呈现（icon + 说明 + 下一步操作入口，如「可在『持仓监控』页录入」）
- 任务失败：任务区红色明细 + 重试按钮（现状保留）

### 5.3 操作交互统一规则

- 高频操作（触发挖掘/监控/生成方案）统一 `type="primary"`，置于页面操作区固定位置
- 破坏性操作（删除知识/驳回建议）需二次确认或表单必填原因（现状保留）
- 所有「提交后立即 rerun」的按钮保留现有行为；避免页面假死：任何 LLM 调用都不在按钮事件内同步阻塞（已统一异步，本次不引入新阻塞点）
- 筛选/切换一律不加全页延迟；查询类切换条件后列表回到首屏（候选池现状逻辑推广）

## 6. 深色科技感视觉落地规范

### 6.1 颜色体系（CSS 变量集中定义，全站唯一来源）

```css
:root {
  /* 背景分层：页面 < 卡片 < 悬浮层 */
  --bg-base:      #0B0D13;   /* 页面底 */
  --bg-card:      #141824;   /* 卡片底 */
  --bg-hover:     #1A1F2E;   /* 卡片悬停/激活 */
  --bg-input:     #0F1220;   /* 输入控件底 */

  /* 边框（细线高亮） */
  --border:       #2C2F36;   /* 常规边框 */
  --border-hi:    #3D4460;   /* 卡片描边/高亮 */

  /* 主色 */
  --primary:      #3B82F6;   /* 科技蓝：标题/主按钮/激活 */
  --primary-dim:  #1E3A5F;   /* 选中底色 */

  /* 状态色（A股：红涨绿跌，饱和度适中） */
  --up:           #F87171;   /* 涨/盈利 */
  --down:         #4ADE80;   /* 跌/亏损 */
  --warn:         #F59E0B;   /* 警告/紧急信号 */
  --err:          #EF4444;   /* 错误 */
  --ok:           #22C55E;   /* 成功 */
  --info:         #60A5FA;   /* 信息 */

  /* 评级色 */
  --tier-a:       #F87171;   /* A 深红 */
  --tier-b:       #FBBF24;   /* B 橙 */
  --tier-c:       #60A5FA;   /* C 蓝 */

  /* 文字 */
  --text:         #E5E7EB;   /* 正文 */
  --text-dim:     #9CA3AF;   /* 次要 */
  --text-mute:    #6B7280;   /* 弱化 */
}
```

### 6.2 卡片布局参数（全站统一）

- 圆角 `10px`；边框 `1px solid var(--border-hi)`；阴影 `0 2px 10px rgba(0,0,0,.35)`（轻微悬浮感）
- 内边距 `0.9rem 1.1rem`；卡片间距垂直 `0.7rem`
- 标题：16px/600 字重 + 左侧 3px 主色竖条（区分层级）

### 6.3 排版规范

- 标题层级：`st.title`（页级）→ `st.subheader`（分区，统一带主色小竖条）→ 卡片标题（16px 600）
- 正文 15px，次要 13px；数字一律等宽：`font-variant-numeric: tabular-nums` + 系统等宽栈（Consolas/Menlo/monospace），金额千分位、百分比 1 位小数
- **核心数据高亮**（总资产/总盈亏/指数点位/关键价位）：18px/700 + 微发光 `text-shadow: 0 0 12px rgba(59,130,246,.35)`，仅限顶部栏与各页核心指标卡，禁用泛滥

### 6.4 顶部状态栏（现有 CSS 保留，微调）

- 现有参数保持：`top: 2.95rem; z-index 998; align-items: center; line-height: 1.5; padding: 0.3rem 1rem`（已通过测试验证不偏移）
- 微调：按钮行不再用 `st.columns` 占列，改为状态栏内 inline 按钮（`border: 1px solid var(--border-hi)` 小按钮），主内容区宽度不损失
- 单行约束：`flex-wrap: wrap` 保留，窄屏自动折行不溢出

### 6.5 微动效规则

- 适用场景与时长：卡片悬停 `background: var(--bg-hover) + border-color 变亮`，`transition: all .2s ease`；按钮 hover 背景 0.2s；徽章无动效
- 禁止：大面积复杂动画、无限循环动画、入场动画（性能底线 + 不喧宾夺主）

### 6.6 图表配色（当前无图表，预留）

K线/雷达/资金流图统一：坐标轴 `var(--text-mute)` 低对比、网格线 `var(--border)` 细线、数据线用 `--up/--down/--primary` 高亮、深色底 `var(--bg-card)`（预留扩展，本次不实施）。

## 7. 落地可行性说明

| 项 | 说明 |
|---|---|
