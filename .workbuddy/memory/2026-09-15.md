## 🔴 第一硬规则：单目标必须完全保证质量达标的完成开发（sir 2026-09-16 拍板，永久生效）

**sir 原话**：「就一个目标 要完全保证质量达标的完成开发， 要不然最后会相差甚远的」

**含义**：

- **单目标 = 一次只做一件事，但必须做到 100% 验收**
- **不接受"功能 95% / 测试 88% / 数据 0%"**——这种"半成品"交付，**最后会相差甚远**
- **半成品的代价 = 真实跑发现 0 条 + 1 例测试 fail + 等等**——用户必须回来"擦屁股"
- **真正的"反机械洁癖" = 一次做好做满**，**不是**"差不多就 commit"

**vs 之前"反机械洁癖"区分**（重要）：
- ❌ 之前"反机械洁癖"理解错：把"追 trailing whitespace / 反复压行数"当机械洁癖
- ✅ 真正的"反机械洁癖"：**业务功能 / 测试 / 真实数据落库**必须 100% 达标，**这些不是洁癖，是质量**

**新铁律**（永久生效）：

1. **单目标 = 一次只做 1 件事**（避免 v1→v2→v3→v4 反复）
2. **但做完 = 100% 验收**（不只 commit，**必须真实跑通**）
3. **不接受的"半成品"**：
   - ❌ 5 个脚本跑 4 个 + 1 个落库 0 条
   - ❌ 7 passed 1 failed 强行 commit
   - ❌ 功能 100% 但 fixture 写错
   - ❌ 真实数据空，mock 数据 OK
4. **接受的边界**：
   - ✅ 业务功能 100% + 已知 1 处小 bug 留未来修（**但必须明示**）
   - ✅ 守则触发熔断（环境失败 × 2）→ 立即停，**不**硬扛

**执行判断表**：

| 状态 | 行动 |
|---|---|
| 4 脚本跑通 + 1 脚本 0 落库 | **不** commit，**修完**再 commit |
| pytest 7 passed 1 failed | 修 1 例 fixture 再 commit，**不**带 skip |
| 业务功能 100% + 已知 1 行 bug | 透明标注 commit，**不**当"半成品" |
| 连续 2 次失败（环境问题） | 立即停，**不**硬扛 |

- ❌ `test_end_to_end.py` 7 passed 1 failed 仍 commit

**今日正面**（要做）：

- ✅ 单次 v1（150-250 行）写完就发
