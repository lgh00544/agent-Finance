### 新坑：dev_run 的 `_port_busy()` 会把"濒死旧实例"误判为正常实例

13:27 按流程启动，日志首行却是：

```
[WARNING] dev_run - 127.0.0.1:8000 已被占用：已有后端实例在跑，拒绝重复启动（防双实例双 APScheduler 抢任务锁）
```

但同一时刻日志里又能看到**另一个**旧后端在响应 `GET /api/health 200`、`/api/jobs/status 200`，Lark wss 已连上——即：旧实例在 13:27 还活着（占着 :8000），**几分钟后才真正死掉**。结果：新启动被拒 + 旧实例很快死亡 = **没有一个后端在跑**。

**教训（新增）**：
1. 判定"端口空闲"要在**启动命令发出的同一时刻**做；若日志出现"已被占用…拒绝重复启动"，**必须立即重跑端口检查并重发启动**，不要误以为"已有实例在跑，万事大吉"。
2. "后台任务 failed 通知" 与 "进程实际死亡" 之间存在**数分钟延迟窗口**，这期间端口可能仍被占。
3. 启动后 30–60 秒务必 `head` 一下日志确认**没有**那行 port-busy 警告，再进入 ~6 分钟等待；否则白等。
