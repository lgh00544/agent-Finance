### 🔴 我补出根因（报告只找到下游症状）
`backend/app/datasource/akshare_source.py:1173-1178`：
```python
def _call_with_timeout(self, func, *args, **kwargs):
    """优先传 timeout，接口签名不支持时降级不带超时调用"""
    try:
        return func(*args, **kwargs, timeout=settings.datasource_timeout)
    except TypeError:
        return func(*args, **kwargs)      # ← 降级调用【完全无超时】
```
- **凡是签名不接受 `timeout` 的 akshare 接口（如 `stock_financial_analysis_indicator`），降级分支即裸调 → 无任何超时 → 永久挂起**。这才是 CPU=0、stderr 冻结 100 分钟的源头。
- `except TypeError` **捕获过宽**：本意是"签名不支持 timeout"，但任何 TypeError 都会被吞并**重试一次无超时调用**。
- ⇒ 与报告的护栏缺陷是**两个独立层**：护栏 = 没有断路器；`_call_with_timeout` = 没有超时。**修后者更根本。**

### 修复方向（供排期）
1. **根治**：降级分支也要有硬超时（线程池 `future.result(timeout=)` 或统一 `socket.setdefaulttimeout`）。
2. **断路器**：护栏改为能中断进行中的调用（独立 watchdog），并向 `_job_reason` 上报。
3. **分诊**：`run_factor_ic_backtest_job` 用 try/except 包住取数段，把异常转成 reason（含「数据源降级」），
   避免裸崩（cron 层 `jobs.py:185-193` 已有 try/except 但只记 log、无结构化 reason）。
