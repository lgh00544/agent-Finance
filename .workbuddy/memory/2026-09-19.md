## 二、量具缺陷：`signal_check.py` / `log_scan.py` 静默假阴性 —— 已修（v2）

- 症状（09-18 实录）：`signal_check.py` 报「完成行=0 / 异常文案全 0 / 未发现当日执行痕迹」，**而实际已执行且命中 5 条异常文案** → 把失败 run 误报成"未执行"。
- 根因：硬编码 `raw.decode("gbk", "replace")`，而 **09-18 14:03 起日志实为 UTF-8**（`decode("gbk")` 在第 307 字节即抛错；`decode("utf-8")` 成功且 4 个中文探针全命中）→ 中文被打成替换字符 → 探针 0 命中。
- 修法（**只动量具，未触碰被观测系统**，不属「观察期不改码」红线）：
  1. `decode_auto()`：utf-8 优先 + **以 ASCII 锚点**（`app.services.signal_scan` / `apscheduler` / `Traceback` / `[INFO]`）判定解码成功，gbk 回落，并输出每文件所用编码
  2. 日志来源：只扫 live → **live + 全部 `backend-dev.stdout.*.log` 归档合并、逐行去重**（进程重启会覆盖 live）
  3. 判定：只判「有无完成文案」→ **解析 summary 的 `reason`**，`reason != ok` 一律判异常日
- 修复后复跑 09-18 → 输出与上表完全一致，结论 **❌ 异常日** ✅
- 遗留限制：**09-16/09-17 归档日志中文已被 U+FFFD 污染**（旧进程编码问题），中文探针在那些文件上无效
