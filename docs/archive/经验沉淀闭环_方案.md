## 3. 批 1+2+3 范围

### 批 1:collect 段合并重复(主因)
- **改动**:`db/repo.py:add_pending_experience` 之前,加合并层
- **方案**:同 `(stock_code, signal_type, hour_bucket)` 已 pending → 不再 insert 新行,改为更新 `artifacts_ref` += count
- **文件**:`db/repo.py:2055-2063`(改 1 函数)+ `graph/router.py:83`(不改,只走新接口)
- **数据**:`artifacts_ref` 现有是整数 ID,扩为 `JSON {count, first_at, last_at}`
- **风险**:扩字段 → 改 schema,需补 migration / 兼容旧数据(读时 JSON parse 失败→按 int 旧逻辑)
- **新增**:`merge_pending_duplicate(task_id, stage, summary, artifacts_ref)` 函数,先查后 insert
- **验证**:5 例(无重复/有重复 1/有重复 3+ 合并/不同 hour 不合并/不同 stock 不合并)

### 批 2:EXTRACT_SYSTEM 持续信号维度
- **改动**:`agent_prompts/experience_prompt.py:8-26` 加"持续信号"判定规则
- **新增维度**:看到 `artifacts_ref.count >= 3` → `worth=True` + `title=「持续信号:X 标的在 N 次 hold/reduce 反复」+ impact=low`
- **文件**:1 文件,~20 行新增
- **风险**:LLM 输出形态变化 → 需测试 3 例(常规 worth=False / 常规 worth=True / 持续信号 worth=True)
- **不动**:`ExperienceDraft` schema(stage/impact/confidence 已够用)

### 批 3:M5 设置中心配置热加载
- **改动**:`experience_config` 落库默认 5 条(`worker_cron/worker_model/confidence_threshold/auto_merge_enabled/worker_sleep_sec/digest_backlog_threshold`)
- **新增端点**:`/api/experience/config`(GET 全部 / PUT 单条) → M5 UI 可改
- **文件**:`api/routes.py` 加 2 端点 + `db/repo.py` 加 `set_experience_config` 函数
- **不动**:`services/experience_worker.py:_cfg/_cfg_int/_cfg_bool`(已有读 DB 逻辑)
- **M5 UI**:暂不实现(留给后续,本批只把后端闭环)

## 4. 红线(不可越)

1. **Agent 解耦** — 绝不动 `graph/router.py` 路由逻辑,只走新 `add_pending_experience` 接口
2. **不引新库** — 复用 SQLite + 已有 schema
3. **不删旧数据** — `artifacts_ref` 扩字段读时兼容(try JSON except int)
4. **不破坏 Worker** — `_process_item` 行为不变,只是 source 数据更干净
5. **不写新 LLM 提示** — 只在现有 EXTRACT_SYSTEM 加规则,不动结构
6. **不引新组件** — 前端 0 改动(本批纯后端)
7. **不写 commit** — 走原工作流
