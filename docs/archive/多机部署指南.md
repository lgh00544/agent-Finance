# 多机部署指南（共享云端 TiDB 主库）

> 适用：**第二台（及更多）电脑**接入同一套系统，与主电脑**共用同一个云端 TiDB 数据库**——
> 主电脑录入的持仓、跑出的候选池/评分/复盘，另一台电脑打开面板**实时看到同样的数据**。
> 本指南为「共享主库」模式；想单机独立跑（本地 SQLite）请看《新机器部署指南.md》。

---

## 0. 原理（先花 30 秒看懂）

```
主电脑 ──┐
         ├──→ 云端 TiDB（stock_agent 库）◄── 所有电脑的数据都在这，天然共享
另一台 ──┘
```

- **数据在哪**：业务数据（候选池/评分/持仓/复盘/偏好/知识库/告警…）全部存在云端 TiDB。
  git 只同步**代码**，不同步数据——数据共享靠的是 TiDB，不是 git。
- **每台电脑自己有哪些（不共享）**：`.env`（含 TiDB 密码等密钥，严禁入库）、
  向量库（Qdrant 本地文件，新闻索引各机独立，不影响业务数据）、LLM 缓存（进程内存）。

## 3. 配置 .env（关键步骤，密码不共享到代码）

```bash
copy .env.example .env
```

用记事本打开 `.env`，**必须改这 7 处**（其余可保持默认；密钥类按需填）：

```ini
# 主库 = 云端 TiDB（多机共享），不是本地 sqlite！
DB_BACKEND=mysql

MYSQL_HOST=gateway01.ap-southeast-1.prod.aws.tidbcloud.com
MYSQL_PORT=4000
MYSQL_USER=oqB7RfrACxSzYuA.root
MYSQL_ROOT_PASSWORD=＜从主电脑 .env 复制＞
MYSQL_DATABASE=stock_agent

# 可选，但建议填（LLM 必填）
DEEPSEEK_API_KEY=＜你的 DeepSeek Key＞
```

⚠️ 三件事：
1. **密码只放 .env**，不要发到聊天/代码/文档里；
2. `.env` 已被 git 忽略，不会随代码同步——**每台电脑都要自己配一次**；
3. SSL 连接已内置在代码里（TiDB 强制 TLS），无需在 .env 配证书。

## 4. 启动（照抄）

```bash
# 终端 1：后端 API + 定时任务（端口 8000）
.venv\Scripts\python backend\scripts\dev_run.py

# 终端 2：Streamlit 面板（端口 8501）
```

浏览器打开 http://localhost:8501 —— 看到的数据与主电脑**完全相同**（同一云端库）。

### 验证是否真的连上了 TiDB（而不是本地库）

```bash
.venv\Scripts\python sync_manager.py check
# 输出 [OK] 连通 ... 8.0.11-TiDB-v8.5.3-serverless 即成功
```

## 5. 多机注意事项（重要）

| 事项 | 说明 |
|---|---|
| **定时任务会双跑** | 每台电脑的 `dev_run.py` 都会启动调度器（16:10 挖掘、盘中监控、龙虎榜…）。两台同时在线时同一任务会跑两次——落库按唯一键覆盖，**不会产生重复数据**，但会**重复消耗 API 额度**。建议：只在一台电脑开 `dev_run.py` 当「主调度机」，另一台只开面板；或接受双跑。 |
| **向量库不共享** | Qdrant 是本地文件模式（`data/qdrant_storage/`），新闻向量索引各机独立。候选/评分等业务数据不受影响；新机首次打开「新闻核实」模块会先本地重建索引。 |
| **本地冷备可选** | 每台电脑都可配 Windows 计划任务定时拉云端快照到本地（断网可查）：`schtasks /Create /TN "stock_sync_backup" /TR "\"<项目路径>\.venv\Scripts\python.exe\" \"<项目路径>\sync_manager.py\" backup" /SC DAILY /ST 17:30 /F` |
| **断网降级** | 云端不可达时后端会报错（连不上库）；此时可改回 `DB_BACKEND=sqlite` 用最近一次本地快照查看（快照由 `sync_manager.py backup` 生成在 `backup/`，或 `restore` 恢复）。 |
| **同时改数据** | 两机同时录入/操作同一持仓以「最后一次写入」为准（无跨机锁），正常单人使用无影响。 |

## 7. 常见问题

**Q1: 启动报 `Unknown database 'stock_agent'`？**
A: 说明这库还没建过。在主电脑跑一次 `python sync_manager.py init`（建库+建表+灌数据），
或在本机直接跑一次 `init`（会自动建库建表，表结构来自代码，云端已有数据不会丢）。

**Q2: 报 `Connections using insecure transport are prohibited`？**
A: 说明代码不是最新版（SSL 参数在代码里）。先 `git pull` 再启动。

**Q3: 面板能开但数据是空的？**
A: 大概率 `.env` 的 `DB_BACKEND` 还是 `sqlite` 默认值——确认第 3 步改成了 `mysql`，并重启后端。

**Q4: 测试跑不过（连了云端）？**
A: 项目测试已强制走本地临时 SQLite（`conftest.py`），正常跑 `pytest` 不会碰云端。

**Q5: 面板某些模块报错 / 显示「—」？**
A: 当天数据源（东财/新浪）或 LLM 服务不稳定会降级展示，属正常容错；稍后手动刷新重试即可。

**Q6: 同步又失灵了（另一台电脑看不到新数据）？**
A: 90% 是 `.env` 被改回了单机模式。按优先级查：
1. `.env` 里 `DB_BACKEND` 必须是 `mysql`（被改成 sqlite = 本机只写本地，另一台看不到；2026-08-27 踩坑实录，`.env` 里已加 🔴 警示注释）；
2. `MYSQL_HOST/PORT/USER/DATABASE` 是云端 TiDB 那 5 项，不是 127.0.0.1:3306；
3. 跑 `python sync_manager.py check` 验证连通；连通但缺数据 → `python sync_manager.py init`（本地→云端全量 upsert，幂等安全）。
