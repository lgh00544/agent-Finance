## 〇 背景与问题

1. **市场现状**：无单一主升板块，资金每日在不同板块间切换（轮动市）。轮动市的交易逻辑与主线市完全不同——追高易被次日切换打脸，低吸轮动板块更有效。
2. **现有系统缺口**：`sector_snapshot` 只存每日 **top5**（`sector_snapshot.py:55 boards[:5]`），当天覆盖，无全板块排行、无多日历史、无启动原因、无规律统计。
3. **sir 需求**：①记录每天板块前几 ②分析启动原因 ③多时间范围看潜在规律。

## 一 目标

1. **数据底座**：每日收盘后全板块排行落库（不止 top5），保留多日历史
2. **轮动状态判定**：量化"当前是主线市 / 轮动市 / 混沌"（榜首更替率 + 持续性）
3. **启动归因**：每日强势板块（topN）自动分析启动原因（政策/消息/资金/超跌/业绩/外围等）
4. **多窗口规律**：3/10/20/60 日窗口统计轮动周期、板块持续天数、启动→退潮路径
5. **Agent 注入**：MarketIntel collect 段注入轮动状态 + 当日归因，供全 Agent 参考

**不做什么**：
- 不新增 LangGraph 节点（子 Agent 走独立 `agent_call` + 落库，不动主图 6 节点）
- 不做个股级归因（板块级起步）
- 不引入新数据源/新库（复用 akshare 既有接口 + SimpleCache）
- 不做自动交易信号（只做分析参考维度）

## 二 数据底座设计（批次 A）

### 2.1 新表 `sector_daily_snapshot`（全板块每日快照）

```sql
CREATE TABLE IF NOT EXISTS sector_daily_snapshot (
    id INT PRIMARY KEY AUTO_INCREMENT,
    trade_date VARCHAR(10) NOT NULL,          -- YYYY-MM-DD
    sector_name VARCHAR(64) NOT NULL,          -- 板块名
    change_pct FLOAT NOT NULL,                 -- 当日涨幅
    rank_no INT NOT NULL,                      -- 全板块涨幅排名（1~N）
    up_count INT NULL,                         -- 上涨家数
    down_count INT NULL,                       -- 下跌家数
    volume_ratio FLOAT NULL,                   -- 量比（东财，缺失如实 NULL）
    turnover_rate FLOAT NULL,                  -- 换手率
    leading_stock_name VARCHAR(64) NOT NULL DEFAULT '',   -- 领涨股
    leading_stock_code VARCHAR(16) NOT NULL DEFAULT '',
    leading_chg FLOAT NULL,                    -- 领涨股涨幅
    source VARCHAR(8) NOT NULL DEFAULT 'em',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    UNIQUE KEY uq_sd_date_name (trade_date, sector_name),
    KEY ix_sd_date_rank (trade_date, rank_no)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

- 与 `sector_snapshot`（top5 盘中快照，首页用）**并存不替代**
- 触发：每日 **15:35** cron（收盘后）全量抓一次，删后插（仿 `repo.upsert_sector_snapshot:218`）
- 数据源：`fetch_industry_spot`（akshare 东财行业板块，已有断路器 + 缓存）
- 字段口径：东财列 `up_count/down_count/volume_ratio/turnover_rate` 已映射在 `_BOARD_COLS:93-98`；缺失如实 NULL（K227 不编造）

### 2.2 追加表 `sector_daily_rank_log`（轮动指标快照，批次 B 复用）

```sql
CREATE TABLE IF NOT EXISTS sector_daily_rank_log (
    id INT PRIMARY KEY AUTO_INCREMENT,
    trade_date VARCHAR(10) NOT NULL,
    rotation_state VARCHAR(16) NOT NULL,       -- 'mainline' / 'rotation' / 'chaos'
    churn_rate FLOAT NULL,                     -- 榜首更替率 0~1
    top5_overlap INT NULL,                     -- 与昨日 top5 重叠数
    mainline_sector VARCHAR(64) NULL,          -- 主线候选（连续居前板块）
    notes VARCHAR(255) NOT NULL DEFAULT '',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    UNIQUE KEY uq_rd_date (trade_date)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

### 2.3 追加表 `sector_launch_reason`（启动归因，批次 C 复用）

```sql
CREATE TABLE IF NOT EXISTS sector_launch_reason (
    id INT PRIMARY KEY AUTO_INCREMENT,
    trade_date VARCHAR(10) NOT NULL,
    sector_name VARCHAR(64) NOT NULL,
    rank_no INT NOT NULL,
    reason_tags VARCHAR(128) NOT NULL DEFAULT '',   -- 逗号分隔：policy/news/fund/oversold/earnings/overseas/rotation
    reason_text TEXT NULL,                           -- LLM 一句结论
    reason_chain TEXT NULL,                          -- LLM 分析过程证据链（sir 要求：通过什么消息/数据判定）
    evidence JSON NULL,                              -- 代码层事实证据（量比/换手/资金/箱位/领涨股连板）
    confidence FLOAT NULL,                           -- LLM 置信度 0~1
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    UNIQUE KEY uq_lr_date_name (trade_date, sector_name)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

> v2 变更：`reason_chain` 为新增列——LLM 必须输出归因推导过程（例：抓到领涨股「XX」新闻标题含「政策」→ 判 policy），前端归因卡片可展开查看。

## 三 轮动状态判定（批次 B，`services/sector_rotation.py` 新建）

### 3.1 核心指标（纯代码，无 LLM）

| 指标 | 定义 | 用途 |
|---|---|---|
| 榜首更替率 churn | 1 − (今日 top5 ∩ 昨日 top5)/5 | 轮动速度；>0.8 强轮动 |
| 持续天数 streak | 板块连续居 top5 天数 | 主线候选；≥3 日判主线 |
| 强度分位 pct_rank | 板块当日涨幅在近 20 日自身涨幅中的分位 | 识别"启动"vs"高位" |
| 累计强度 cum5/cum20 | 近 5/20 日累计涨幅 | 主线 vs 脉冲 |

### 3.2 状态机（阈值先行，LLM 一票否决权保留）

| 状态 | 判定条件（代码） |
|---|---|
| `mainline` 主线市 | 存在板块 streak≥3 且 top3 当日仍在 |
| `rotation` 轮动市 | churn≥0.6 且无 streak≥3 板块 |
| `chaos` 混沌 | 前两者都不满足（如普涨/普跌日） |

- 判定结果落 `sector_daily_rank_log`
- **红线**：阈值（churn 0.6 / streak 3）先定死，后续如需调走 review_log 审计

### 3.3 板块箱位/位置（复用 `fetch_board_box_positions:1048`）

- 对 top5 板块算 10 日主箱位 + 60 日箱位 → 区分"突破启动"vs"箱顶接力"vs"低位超跌反弹"

## 四 启动归因（批次 C，`services/sector_launch_reason.py` 新建）

### 4.1 代码层事实采集（每板块，只做数据打包）

| 证据字段 | 来源 | 说明 |
|---|---|---|
| volume_ratio / turnover | 已落库 | 放量启动信号 |
| up/down_count | 已落库 | 普涨度 |
| leading 连板数 | `fetch_daily_kline:924` 查领涨股近 5 日 | 龙头强度 |
| 主力净流入 | `fetch_fund_flow:956`（领涨股） | 资金面 |
| 板块新闻热度 | `fetch_news:1017`（领涨股近 1 日条数） | 消息面 |
| 箱位突破 | batch B 已算 | 位置面 |
| 大盘量能 | `fetch_market_total_volume_ratio:824` | 环境面 |

### 4.2 板块轮动子 Agent（v2：新增独立子 Agent，供候选池宏观评定调用）

**sir 拍板**：新增一个**每日候选池的子 Agent**（板块轮动分析 Agent，命名 `sector_rotation_agent`），职责单一：宏观板块分析（轮动状态 + 强势板块启动归因）。候选池总 Agent 在宏观评定时调用它，与其他子 Agent（量价/风控/前瞻等）结果汇总后统一评定。

**架构定位**（与现有 Discover 子 Agent 模式一致，`discover.py` 已有多子 Agent 自我扮演先例）：
- 不新建 LangGraph 节点、不动 `graphs.py` 主图（`graph/graphs.py:20-32` 保持 6 节点不动）
- 作为**独立子 Agent**：单独 LLM 调用（复用 `common.agent_call`），产出落库
- 候选池总 Agent（`llm_final`）通过 `build_final_prompt` 注入该子 Agent 结果文本段（仿 `hot_money_context` / `horizon_context` 注入模式，`discover.py:667-676`）

**运行策略（sir 拍板）**：
- 每日固定 1 次（cron 15:35 收盘后，与全板块快照同批触发）
- **以当日最后一次为准**（手动触发/补跑覆盖当日结果，同 trade_date 删后插）
- **手动触发入口**：API `POST /api/market/sector-rotation/run`（仿既有手动触发接口风格），前端 MarketIntelPage 放「立即重跑」按钮

**LLM 归因输出 Schema**（sir 要求输出分析过程，不只结论）：

| 字段 | 含义 | 示例 |
|---|---|---|
| reason_tags | 归因标签（可多选） | policy,news |
| reason_text | 一句结论 | 「政策+消息共振推动」 |
| **reason_chain** | **分析过程证据链**：写明通过哪些消息/数据判定 | 「领涨股 XX 新闻《…》涉政策 → 判 policy；板块量比 2.1 → 资金进场」 |
| evidence | 代码层事实 JSON | {volume_ratio: 2.1, up_count: 32, ...} |
| confidence | 置信度 0~1 | 0.82 |

**缺数据兜底**：任一证据缺失 → 字段 null，prompt 明示"数据缺失"，LLM 不得编造（K227）。reason_chain 中引用的每条证据必须是 evidence 里存在的字段。

## 五 多窗口规律分析（批次 D，`services/sector_rotation_pattern.py` 新建）

### 5.1 统计窗口与输出

| 窗口 | 回答的问题 | 输出 |
|---|---|---|
| 3 日 | 短线轮动节奏 | 轮动周期天数、今日板块 vs 前 2 日重叠率 |
| 10 日 | 周线主线 | 各板块累计强度 top10、持续天数分布 |
| 20 日 | 月度主线 | 主线候选（streak≥5）、板块强度梯队 |
| 60 日 | 季度趋势 | 板块趋势斜率、是否长期走强 |

### 5.2 规律挖掘（可验证假设，落 `sector_daily_rank_log.notes` 或前端展示）

1. **轮动周期**：top5 全换一轮平均需要几天（churn 时间序列自相关）
2. **启动→退潮路径**：强势板块从 top1 到跌出 top10 平均持续几天（生命周期）
3. **板块间轮动方向**：高切低（前日强→今日弱 vs 前日弱→今日强）的频次统计
4. **启动成功率**：满足"放量（量比>1.5）+ 突破箱位（主箱位>0.8）"条件的板块，次日仍在 top10 的概率

### 5.3 输出形态

- 前端「板块轮动」页（React MarketIntelPage 或独立 Tab）：每日 top10 + 轮动状态徽章 + 启动原因卡片 + 规律表
- API：`/api/market/sector-rotation`（当日状态 + top10 + 归因）、`/api/market/sector-patterns`（多窗口规律）
