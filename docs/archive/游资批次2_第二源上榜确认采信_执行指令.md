# 游资批次2 龙虎榜第二源采信升级

## 目标
让龙虎榜多源采信真正"可用"：当前 `second_source_status()` 硬编码 `available=False`，新浪代码已接入但不作采信依据。本批把新浪作为**上榜确认第二源**真正参与采信（金额仍以东财为准），`available` 动态反映真实第二源可用性，对齐 K227"如实标注、单源不采信、双源共识升级"。**只改 `backend/app/datasource/dragon_tiger_source.py` 单文件**，后端调度/注入消费方（jobs.py / hot_money.py）不动。

## 改动点

| 位置 | 改动 | 备注 |
|---|---|---|
| `_SECOND_SOURCE_CANDIDATES`（L32-35） | 保留 ths/sina 说明；新增 `eastmoney` 主源说明条目 | 让 candidates 如实反映主源+候选 |
| `second_source_status()`（L38-48） | 移除硬编码 `available=False`；改为**动态探测**：传入可选 `sina_fetched: bool`（新浪是否拉到上榜确认数据）参数，`available = sina_fetched`；annotation 随状态变化（true→"双源：东财金额+新浪上榜确认（金额以主源为准）"，false→保持"当前仅东财、采信待第二源"） | 零网络调用仍成立（探测结果是调度/抓取端传入的布尔，不在本函数发请求）|

## 说明
回落到新浪上榜确认第二源（金额缺失、仅确认上榜）作为本批第一版接入；同花顺仍不可用（hexin-v token）。available 动态反映真实第二源是否已参与。

## 红线
1. 只改 `backend/app/datasource/dragon_tiger_source.py`；禁止动 jobs.py / hot_money.py / config.py / 前端

4. 不伪造第二源金额：新浪无净额列 → 仅作上榜确认标签，绝不合并进净买额
5. 不改动现有 `test_dragon_tiger_source.py` 断言（confidence=0.8 保留）；若有新断言可选加
